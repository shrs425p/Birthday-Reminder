1) PROJECT OVERVIEW
====================================================================
Project Name:
Birthday Reminder

Project Type:
Web application for managing student birthday records, reminders, and
email-based birthday wishes.

Primary Goal:
- Maintain birthday records
- Allow student-side correction requests
- Provide admin-side approval and management
- Support manual and automatic email wishes

Core Modules:
- Public Home page
- Public Student page
- Admin panel (authenticated)
- Backend APIs
- Scheduler and SMTP integration

====================================================================
2) PROBLEM STATEMENT AND OBJECTIVES
====================================================================
Problem:
Institutions often track birthdays manually, which leads to missed wishes,
incorrect records, and no audit trail for corrections.

Objectives:
- Centralize birthday data
- Offer quick public visibility of birthdays
- Enable correction requests without requiring student login
- Secure admin operations with token-based auth
- Automate wish sending through SMTP and scheduled jobs

9) WORKFLOW (END-TO-END)
====================================================================
A) Home flow
1. Browser loads index page
2. Frontend calls:
   - GET /api/birthdays/today
   - GET /api/birthdays/upcoming
   - GET /api/birthdays
3. UI renders today cards, upcoming cards, stats

B) Student correction flow
1. Student submits correction form
2. POST /api/requests
3. Record inserted with pending status
4. Admin sees request in Requests tab
5. Admin approve/reject via PUT /api/requests/:id/status

C) Admin login flow
1. POST /api/login with role=admin
2. Backend validates bcrypt hash
3. JWT token returned
4. Token stored in localStorage and sent in Authorization header

D) Email sending flow (manual)
1. Admin configures SMTP in Settings
2. Admin clicks Send Wishes Today
3. API calls birthday wish handler
4. Transporter reads SMTP host/port from env and user/pass from DB settings
5. Emails sent to today's birthday rows with email addresses

E) Email sending flow (auto scheduler)
1. Server starts scheduler
2. Scheduler reads auto_send_time from settings
3. Builds cron expression from HH:MM
4. Executes daily at configured IST time
5. Sends birthday wishes automatically

12) SECURITY IMPLEMENTATION
====================================================================
- JWT secret read from env
- Passwords hashed with bcrypt before DB insert/update
- Auth middleware validates token and role
- SMTP password encrypted before storage (AES-256-CBC)
- Settings endpoint protected with requireAuth + requireAdmin
- Admin routes protected
- Student and Home routes intentionally public by design
